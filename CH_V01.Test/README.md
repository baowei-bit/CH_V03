# CH_V01.Test

TCP 下位机模拟测试程序。本程序作为 TCP Server 运行，CH_V01 测试系统作为 TCP Client 连接进来。

## 运行

```powershell
dotnet run --project .\CH_V01.Test\CH_V01.Test.csproj
```

默认监听 `127.0.0.1:15000`。

指定端口和监听地址：

```powershell
dotnet run --project .\CH_V01.Test\CH_V01.Test.csproj -- 15000 0.0.0.0
```

## 测试系统配置

在 CH_V01 测试系统中，将下位机通讯方式配置为：

- 通讯方式：`TcpClient`
- IP：测试程序监听的地址
- 端口：测试程序监听的端口，默认 `15000`

如果测试系统和测试程序在同一台电脑，IP 可使用 `127.0.0.1`。

## 命令

- `/start`：发送启动信号 `DM\r\n`
- `/partial`：发送一段没有 `end` 的未完成测试结果，用于模拟急停前残留数据
- `/reset`：发送急停/复位信号 `reset\r\n`
- `/items`：发送测试项列表
- `/pass`：发送 PASS 测试结果
- `/fail`：发送 FAIL 测试结果
- `/demo`：依次发送启动信号、测试项列表、PASS 结果
- `/send <text>`：发送自定义报文，支持 `\r` 和 `\n`
- `/quit`：退出程序

## 注意

如果 CH_V01 中点击的是“通讯测试”，客户端会在连接成功后立即断开，这是短连接验证行为。要持续接收本程序发送的测试项和测试结果，需要在 CH_V01 主界面执行设备连接，让下位机连接保持在线。

常用联调顺序：

1. 启动本程序。
2. CH_V01 下位机配置为 `TcpClient`，IP/端口指向本程序。
3. 在 CH_V01 中执行设备连接，看到本程序显示 `Client connected`。
4. 在本程序输入 `/items` 发送测试项，或输入 `/pass`、`/fail` 发送测试结果。

## 急停恢复回归流程

1. 连接后先输入 `/items`，只加载一次测试项目表。
2. 输入 `/start`，按当前扫码模式完成扫码并开始第一轮测试。
3. 依次输入 `/partial`、`/reset`，模拟第一轮数据未发送完时急停。
4. 急停后再次输入 `/pass`，确认该旧周期结果被忽略，不生成结果记录和文件。
5. 输入 `/start`，完成第二轮扫码后直接输入 `/pass`，不要再次输入 `/items`。
6. 确认日志出现“已收到新的 DM 信号，恢复接收本周期测试结果”和“测试结束：PASS”，并确认第二轮结果已写入产量记录及导出文件。
