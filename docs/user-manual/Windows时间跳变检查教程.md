# Windows 时间跳变检查教程

适用范围：嘉联益测试工站出现测试时间明显偏短、偏长或为负数时。  
目的：确认 Windows 系统时间是否在测试过程中被自动校时或人为修改。

> 测试程序的开始、结束时间目前取自 Windows 系统时间。因此系统时间在测试中前跳或回拨，会直接造成 CSV 内的 `TestTime` 异常。

## 一、先记录异常发生时间

1. 在测试 CSV 中记录异常 SN、`StartTime`、`EndTime`、`TestTime`。
2. 在 CeHao 运行日志中记录该 SN 的 `sendLowerCom:DMOK`、`RecLower:Test...` 和“测试结束”时间。
3. 记录异常前后各 **5 分钟** 的时间范围。例如异常发生在 `2026-08-25 10:14`，检查范围为 `10:09` 至 `10:19`。

## 二、在 Windows 事件查看器中检查

### 方式 1：从开始菜单打开

1. 按键盘 `Win` 键，输入“事件查看器”。
2. 点击打开 **事件查看器**。
3. 左侧依次展开：

   `Windows 日志` → `系统`

4. 右侧点击 **筛选当前日志…**。
5. 在“事件来源”中优先选择以下项目（不同 Windows 版本显示可能略有差异）：

   - `Microsoft-Windows-Time-Service`
   - `W32Time`
   - `Kernel-General`

6. 在“已记录”中选择“自定义范围”，填写第一部分记录的异常前后 5 分钟。
7. 点击“确定”，查看该时间范围内的事件。

### 方式 2：通过运行窗口打开

1. 按 `Win + R`。
2. 输入 `eventvwr.msc`，点击“确定”。
3. 后续操作与“方式 1”的第 3～7 步相同。

## 三、重点查看的事件

双击可疑事件，查看“常规”页中的详细说明；重点寻找以下文字：

| 现象或关键字 | 说明 | 判断 |
| --- | --- | --- |
| `系统时间已更改` / `The system time has changed` | Windows 系统时钟被修改 | 可直接确认时间跳变 |
| `Time-Service`、`W32Time`、`同步`、`synchronized` | Windows 从时间服务器校时 | 若发生时间与异常测试重合，即为高风险原因 |
| `NTP`、`域控制器`、`time.windows.com` | 校时来源 | 记录来源，交由 IT 排查 |
| 时间一次跳动数秒或数十秒 | 时间并非正常连续流逝 | 会导致测试时长偏短、偏长或负数 |

特别注意：若日志顺序中后一条记录的时间反而更早，例如 `10:14:58` 后变成 `10:14:05`，即可确认系统时钟发生了回拨。

## 四、用命令检查当前时间同步状态

> 此步骤只读取状态，不会修改系统配置。

1. 右键开始菜单，选择 **终端（管理员）** 或 **Windows PowerShell（管理员）**。
2. 依次执行以下命令：

```powershell
w32tm /query /status
w32tm /query /source
w32tm /query /peers
```

3. 截图或复制输出内容。

重点关注：

- `Source`：当前时间来源。若显示域控、NTP 服务器或 `time.windows.com`，说明正在自动同步。
- `Last Successful Sync Time`：最近一次成功校时的时间。若与异常测试时间接近，需要重点排查。
- `Stratum`：时间层级；出现异常值或提示未同步时，也需要 IT 检查。

## 五、现场临时处置

1. 不要在测试过程中手动修改 Windows 日期、时间或时区。
2. 不要在测试进行中点击“立即同步”或运行任何校时工具。
3. 若发现校时事件恰好发生在测试中，请通知 IT 检查 NTP/域控时间源是否稳定。
4. 在时间源稳定前，异常 CSV 的 `TestTime` 不应作为真实设备测试时长的依据。

## 六、需要提供给研发的材料

请一次提供以下内容，便于快速定位：

1. 异常 CSV 或 Excel 文件。
2. 对应日期的 CeHao `.log` 文件。
3. 异常 SN 和发生时间。
4. “系统”事件日志中异常前后 5 分钟的截图，需包含“来源、日期和时间、事件 ID、常规说明”。
5. `w32tm /query /status` 与 `w32tm /query /source` 的输出截图。

## 七、本次案例的判定参考

2026-08-25 的日志中已出现多次日志时间倒退：

- `10:00:01.710` 后出现 `09:59:46.013`，造成测试时间被缩短。
- `10:14:58.631` 后出现 `10:14:05.485`，造成 CSV 出现负数测试时间。

这类现象由 Windows 系统时钟跳变引起，不是 MES 返回内容或 CSV 导出本身造成。
