## 员工工号的具体来源

当前界面位置为“插件配置 → 景旺 → 员工上下机 → 员工卡号/工号”。

正常流程：

1. 输入的 EmployeeCardCode 作为员工上机 API 的 CardCode。
2. 上机许可通过后，以返回的 EmpNo 写 PC_DATA_EMP.EMPNO。
3. 同一会话中的检测明细/结果使用当前会话工号。

输入卡号和 API 返回工号可能不是同一个值，二者含义需要区分。

当员工功能或 Web API 关闭时，当前逻辑跳过上机接口及上下机记录。景旺检测上传的 UserNo 仍取 CurrentEmployeeNo，此时可能为空；检测明细/结果并没有额外强制校验工号非空。因此，若要求“关闭上机功能也必须在检测记录中填写员工工号”，还需要独立的生产员工工号配置及非空校验。

CSV 的 user 列目前取 Configuration.Mes.UserNo，与景旺会话 EmpNo 也不是同一个来源。

## GUID 关联

当前数据库四表关联正确：

```text
PC_INSP_DATA.DATAGUID
  = PC_INSPH_DATA.DATAGUID
  = PC_IMG_REL_DATA.DATAGUID

PC_IMG_DATA.IMGGUID
  = PC_IMG_REL_DATA.IMGGUID
```

同一次测试的多条明细共用一个 DATAGUID。一个文件使用一个 IMGGUID，由关系表连接到本次测试；四表采用同一个数据库事务。

本次正式库只读核对仍能通过这两组关联找到 2026-10-23 17:23:18 的记录：274 条明细、1 条结果、1 条 CSV 文件及 1 条关系；对应 CSV 文件实际存在。

需要区分 CSV 内部 guid：ResultExportContext.Guid 当前独立随机生成，单片 CSV 的 guid 列使用这个值；数据库 DATAGUID 按条码和测试时间计算，IMGGUID 则单独生成。数据库关联已成立，但 CSV 内部 guid 尚未统一为其中任何一个值。

若 CSV 内部 guid 也要参与追溯，建议让其统一保存 DATAGUID；文件的 S3 对象标识继续使用独立 IMGGUID，并通过关系表连接。这是待实现的统一方案，不是当前行为。

## 批号、料号和扫码内容

| 数据含义 | 当前来源与落点 | 一致性结论 |
| --- | --- | --- |
| 批号 | 配置 Container → 工艺、读码、检测明细、检测结果的 CONTAINER | 使用同一个配置键，正常不更改配置时一致 |
| 料号 | 配置 Product → 检测明细和检测结果的 PRODUCT | 两表来源一致 |
| 扫码内容 | 读码的 PNLIDORSETID/PARENTID；检测明细的 PARENTID；检测结果的 PCSID | 都使用收到并接受的条码；不扫码模式则使用 NOSCAN 本机编号 |
| SET/PNL 码 | 工艺的 PNLIDORSETID、检测结果的 SETID 当前来自配置 SetId | 当前没有强制与 PCS 扫码内容相同 |
| 明细板序 | 检测明细 PNLIDORSETID 当前也取 SetId | 这里应按用户要求修正为固定 1 |
| CSV config | Configuration.Output.CsvName | 未自动取景旺 Product；不能认为它天然与料号一致 |
| CSV 批号 | 当前没有独立的 Container/Lot 列 | 若要求 CSV 也携带批号，需要增加明确字段 |
| 文件、关系、员工和报警表 | 这些表的原结构并非都含批号/料号/扫码字段 | 文件通过 GUID 关联测试；无需向不存在的列写业务字段 |

扫码写表时和测试完成写表时分别读取配置。如果测试过程中修改 Container/Product，当前没有从扫码开始冻结整笔生产上下文，可能出现跨阶段不一致。待处理的检测补写已保存原工单、批号和料号快照，但这不能替代扫码到完成全过程的上下文冻结。

截图规定的路径规则是：

| 项目 | 示例 |
| --- | --- |
| 人工维护的 S3 文件夹前缀 | ICT/，为空时不拼接前缀 |
| 写入 PC_IMG_DATA.IMGCONTENT 的值 | ICT/<文件标识> |
| FILETYPE | CSV |
| 实际上传到 S3 的 Key | ICT/<文件标识>.csv |

建议以 IMGGUID 作为稳定的文件标识，并在上传前持久保存，保证上传重试仍使用同一个 Key。当前插件还没有 S3 前缀输入框，也没有把本机路径转换为上述对象键。

本地 CSV 路径应继续留作本机追溯；启用 S3 后，IMGCONTENT 应保存供 EAP 取文件的对象键。上传失败需保留待处理状态，避免文件表让 EAP 误以为远端文件已经就绪。

培训 C# 示例需整理后适配现有 .NET 8 工程：文档给了两个同为三个 string 参数的同名构造函数，并存在 serviceUrl/serviceURL 名称不一致。Demo 是 .NET Framework 4.6 程序；其中连接参数可参考，示例代码不宜原样复制为生产插件。HTTP/HTTPS 设置也要与实际 ServiceURL 一致。

S3 ServiceURL 与员工上机、过站、复判的三个 Web API 地址属于不同配置，前者不能代替后三个业务接口。
