覆盖的关键场景：

- 5 分钟默认值和周期边界、无新值不采集、采集中不重入。使用可控时间验证边界，无需真实等待 5 分钟。
- 读码、工艺、报警、员工和各检测/文件开关分别关闭。
- 员工许可拒绝后不写上机记录、不沿用旧会话；下机时不调用任何下机接口。
- Web API 关闭或处于离线时，数据库检测写入仍可执行；保留未过站/未复判状态。
- 不扫码模式保留 NOSCAN 本机测试编号；每日 CSV 和单片 CSV 均有测试数据；检测关系指向单片文件。
- 同一条码两次测试使用不同 DATAGUID，并关联各自文件；同一笔测试重复提交和重建插件不重复写入。
- 在第四张关系表插入时用测试库触发器注入故障，证明前面已执行的明细、结果和文件插入全部回滚；删除测试触发器后人工补写成功。
- 模拟 EAP 取数后删除中间记录，证明本机发送记录仍可识别重复测试。
- 扫码、报警、工艺、员工事件断库时保留本机待处理文件；重建插件后可以人工补写。
- 复判超时、连接不可用、返回其他条码和业务返回失败时，检测数据已写入，复判仍列为待处理。
- 补过站成功而复判失败后，后续人工重试不重复执行已经通过的过站。
- 原始 FAIL 在复判 OK 后不被覆盖；每次复判响应，包括成功和失败，独立保留在本机 `api-history` 中。
- 切换工单和批次后补写旧记录，仍使用旧记录保存的原生产字段。
- 缺少必填参数、CSV 不存在、非 CSV 文件、路径超过 255 字符和冲突的文件开关被拒绝，不产生部分表数据。
- 本机发送 JSON 中不包含数据库密码。

## 本次补齐的边界

1. 工艺采集使用稳定的本机事件 ID；已持久保存的断库事件不再重复排队，需人工补写，不自动重放。
2. 工艺调度独立验证周期及新值状态，已排队数据视为本周期已采集。
3. 成功复判也保留独立历史，且复判返回的条码必须与本笔测试匹配。
4. 未过站时只写检测数据，不自动复判；人工补过站后的状态持久保存，防止下一次重试再次补过站。
5. 新增发送记录保存当时的工单、工序、料号、批次、SET、板序和设备编码；补写时保留原字段。旧版本未保存这些字段的历史文件仍需要人工核对。
6. CSV 路径、文件类型和存在性在事务写入前检查；保留数据库事务作为最终一致性保障。
7. 员工再次上机被拒绝时清空旧会话，避免沿用上一位员工身份。
